# 提示詞骨架庫

> 依任務選用最小足夠骨架；欄位無助於品質時可省略。編寫時的占位符須填妥；正式可重複模板可保留已定義用途與缺值處理的輸入變數。沿用主檔統一交付契約。

## 1. 分析

```
## 任務
分析{{對象}}，回答{{核心問題}}。

## 輸入
{{資料與範圍}}

## 輸出
先給結論，再列關鍵發現、證據、風險與限制。

## 約束
- 每項結論可追溯至輸入或明示來源。
- 事實、推論與假設分開標示。
- 資料不足時指出缺口，不補造細節。
```

## 4. 決策

```
## 目標
針對{{決策}}選出最符合{{目標}}的方案。

## 已知條件
{{資源、限制、候選方案、時限}}

## 評估準則
{{準則與優先序}}

## 輸出
先給建議與依據；存在實質風險、替代方案或改選條件時再說明，不為模板湊選項。

## 約束
區分已知事實、合理推論與待驗證假設。
```

## 5. 除錯

```
## 任務
診斷並修復{{問題}}。

## 環境與證據
{{版本、程式碼、錯誤訊息、預期與實際行為}}

## 流程
1. 根據證據提出最可能根因。
2. 給最小修復。
3. 提供可重現的驗證方式。
4. 若證據不足，先要求最有區別力的診斷資訊。

## 約束
- 不重寫無關內容。
- 不把未驗證假設宣稱為根因。
- 指令須符合指定環境。
```

## 模型適配

- 預設模型中立，不依品牌名稱強加特殊語法或推定工具能力。
- 依實際輸入長度與模態分區，清楚標示來源用途；Markdown、XML 等只在有助於辨識時選用。
- 目標介面已用結構化輸出限制格式時，不在提示詞重複堆疊相同 schema；仍保留語意要求與必要限制。
- 小上下文或能力有限時減少無關分支，必要時加代表性範例，不用固定字數刪掉關鍵規格。
- 版本或功能會影響適配時查目標環境或官方資料；工具綁定依工具契約處理。
